We wanted the browser game to look like an actual game, not an HTML mockup.

So the first change was the asset pipeline. Instead of drawing the protagonist with CSS primitives, we loaded a local GLB character into Three.js.

This character is an original project asset released under CC0, so the render does not depend on a commercial-game character or an unverified “free” download.

From there, the JavaScript controls the runtime state: the character moves through the scene, the run cycle is driven procedurally, obstacles advance through the game loop, and collectibles update their position and animation.

The renderer then captures the actual WebGL output frame by frame.

That gives us the workflow we want: prompt, asset loading, gameplay code, browser execution, verification, and finally the video render.
