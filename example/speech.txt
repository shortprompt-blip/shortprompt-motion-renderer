MotionBricks turns target poses into character motion. It is a pose-conditioned motion system for 3D characters and humanoid robots. It is not text-to-video, and it is not a one-click animation editor. Instead, it predicts movement between a character's recent motion and a set of target poses. In this guide, we will cover the generation logic, system requirements, installation and the first practical interaction. The goal is to understand the workflow before committing time to a local setup and evaluate whether it fits your own development environment.

Four context poses describe recent movement. Target poses define the destination. The model predicts the transition between them. The application chooses the goal; MotionBricks generates the movement needed to reach it. The official release supports two character systems: SOMA for human motion and Unitree G1 for a humanoid robot. The repository includes pretrained models, a Python runtime and interactive developer demos.

The documented project targets Windows and Linux on x86-64, with Python 3.12 or newer. It uses an NVIDIA GPU and TensorRT runtime, alongside Warp and Newton. NVIDIA reports testing the demos on an RTX 4090. Treat that as the documented test configuration, not a universal minimum. Driver, CUDA and TensorRT compatibility, plus available GPU memory, all matter. Check the official requirements before installing, especially on a laptop GPU.

Install Git, Git LFS and uv. Then clone the official repository, enter its folder, pull the large assets and synchronize the environment. The commands are shown here. Git LFS matters because model and motion assets are stored as large files. On the first launch, TensorRT builds a plan for the selected model and precision. That initial setup can take several minutes. Later launches can reuse the cached plan, so do not mistake the first build for normal startup time.

Start with the Inbetweener demo using the SOMA model. The viewer combines a 3D character with a target-pose control panel. Select the End target, move it forward along the character's travel direction, and press Generate. The model predicts a transition from the recent motion to the target. Enable skeleton and velocity views to inspect the result. The four context poses are important: they tell the model how the character was already moving before the new transition begins.

The guided tutorial then builds a duck-under interaction. It samples an Entry pose and a Duck-under pose from a supplied BVH clip. The example uses frames 199 and 328; these are tutorial-specific values, not universal settings. Tokens to Generate controls transition length. Each token produces four raw frames. The tutorial uses eight to fourteen tokens, or thirty-two to fifty-six raw frames. Adjust the count to the distance and action you want, then generate and inspect the full sequence.

A Smart Primitive packages an interaction area, a pivot and target poses into a reusable behavior. The Interaction Box identifies where the action can begin. The pivot rotates and translates the authored sequence, so a character can approach from a different direction. The target poses describe the action inside the area. Scene Preview then combines locomotion, interaction detection and generated motion. For chained motion, the last four played poses become context for the next generation. MotionBricks is a developer integration toolkit: useful for building motion systems, but not a turnkey production app. Check the official repository and docs before planning an integration.
