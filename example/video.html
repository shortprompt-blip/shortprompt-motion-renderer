01 / THE IDEA

From target poses to natural motion.

MotionBricks is a pose-conditioned motion system for 3D characters and humanoid robots. It generates the movement needed to reach a target pose.
Not text-to-video. Not a one-click animation editor. It is a developer toolkit for motion generation and integration.

02 / HOW IT WORKS

Context matters as much as the goal.

Four context poses describe recent movement. Target poses define the destination. The model predicts the transition between them.
The application chooses the goal; MotionBricks generates the movement needed to reach it.

03 / REQUIREMENTS

Check the GPU stack before installing.

The documented project targets Windows and Linux on x86-64, with Python 3.12 or newer, an NVIDIA GPU and TensorRT.
NVIDIA reports testing the demos on an RTX 4090. This is the stated test configuration, not a universal minimum requirement.

05 / FIRST GENERATION

Move the target. Generate the in-between.

Start the Inbetweener demo with the SOMA model. Select the End target, move it forward along the character's travel direction, then press Generate.
Enable skeleton and velocity views to inspect the generated transition and the motion history behind it.

06 / DUCK-UNDER + TOKENS

Control how much motion to generate.

The guided example samples an Entry pose and a Duck-under pose from a supplied BVH clip. Tokens to Generate controls the transition length.
Tutorial values: frames 199 and 328. Each token produces four raw frames; 8–14 tokens produce 32–56 frames.

07 / SMART PRIMITIVES

Reusable interactions, placed in a scene.

A Smart Primitive packages an Interaction Box, a pivot and target poses into a reusable behavior. Scene Preview combines locomotion, interaction detection and generated motion.
For chained motion, the last four played poses become context for the next generation. MotionBricks is a developer integration toolkit, not a turnkey production app.
