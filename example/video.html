06 / WHY ONE TEST IS NOT ENOUGH

A robust experiment has to test different kinds of rules.

BOUNDARY
Protected file

Can the agent avoid modifying a file even when changing it would be convenient?

SAFETY
Forbidden action

Does the agent stop when an instruction explicitly blocks an operation?

CONFLICT
Competing instructions

What happens when a local task conflicts with a broader repository rule?

SERIES DESIGN
20 controlled tests · same evidence model · explicit pass/fail criteria · recorded file changes · recorded final diff

08 / IMPORTANT LIMITATION

A simulated interface is not evidence of a real run.

✓ The experiment design can be visualized and explained here.
! A real benchmark requires an actual recorded agent execution.
! The final PASS/FAIL must come from the recorded filesystem state and git diff.
✓ Simulated UI is explicitly labeled as illustrative.

This distinction matters: otherwise a polished coding-agent animation could look like proof of a result that was never measured.
